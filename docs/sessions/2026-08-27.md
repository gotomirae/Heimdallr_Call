# 2026-08-27 — Provider 중립 LLM 경계와 OpenAI Responses Adapter

## 목표

기존 UI·분석 payload·재무 계산·알림 선정을 바꾸지 않고, Anthropic에 결합된 분석 호출을
Provider 중립 계약 뒤로 옮기고 OpenAI를 선택 가능한 Primary 경로로 추가한다.

## 한 일

- `src/llm/provider.py`에 `LLMRequest`, `LLMResponse`, `NormalizedUsage`, Provider Protocol 추가.
- 기존 Anthropic tool-use/token-count/cache/web-search 동작을 `AnthropicProvider`로 이전.
- OpenAI Responses API의 Structured Outputs와 공식 input-token count 경로를 사용하는
  `OpenAIProvider` 추가.
- `analysis.analyze()`는 SDK 응답 대신 Provider 계약만 읽도록 변경. 기존 함수 시그니처와
  DB `analyses.payload` 계약은 유지했다.
- OpenAI input total에서 cached/cache-write를 빼 `NormalizedUsage`로 만든 뒤 비용을 계산한다.
  그대로 더하면 동일 토큰이 이중 과금된다.
- Provider·모델·단가 설정을 `.env.example`과 LLM 호출 워크플로 3곳에 배선했다.
- 모델명 또는 공식 단가가 없으면 외부 생성·token-count 호출 전에 `UnknownModelError`로 차단한다.
- `openai>=3.5,<4`를 `pyproject.toml`에 선언하고 깨끗한 venv 설치를 검증했다.
- ADR 9와 PRD §5.1/§7.2의 Provider 경계를 기록했다.
- 폴더 이동 뒤 `.venv` editable finder가 옛 `C:\Claude\dev\Heimdallr_Call\src`를 가리키던
  T57 상태를 발견해 `pip install -e ".[dev]"`로 현재 프로젝트 경로에 다시 설치했다.
