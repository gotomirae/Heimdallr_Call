# 2026-08-15 — 텔레그램 봇 분리 + 종목 자동분석 리스너

사용자 요청 2건:
1. HermesCall과 공유하던 텔레그램을 **분리**한다.
2. 새 텔레그램에 **종목명을 언급하면 그 종목 분석이 자동으로** 진행되게 한다.

## 분리 전 상태 (실측)

```
봇 ID      Heimdallr 8605695587  ==  HermesCall 8605695587   ← 완전히 같은 봇
chat_id    sha 27dd0b2d          ==  sha 27dd0b2d
```

토큰·chat_id가 모두 동일했다. 그래서 `setWebhook`이 금지돼 있었다(T13).

## 분리 후

```
Heimdallr  8933940541  @Heinmdallr_bot   ← 신규 전용 봇 (사용자가 BotFather로 생성)
HermesCall 8605695587                     ← 그대로
```

사용자가 `.env.txt`의 `TELEGRAM_BOT_TOKEN`을 새 토큰으로 교체했다.
`chat_id`는 그대로다 — **사용자 본인 ID라 봇이 달라도 같다.**
다만 새 봇에 `/start`를 누르기 전에는 `400 Bad Request: chat not found`가 났다.

## ★ T44 — 이번에 새로 발견한 것

`setWebhook` 금지는 알고 있었는데 **수신 쪽에 같은 크기의 함정이 하나 더 있었다.**

**`getUpdates`는 읽기가 아니라 소비다.** `offset = 마지막 update_id + 1`로 확정하는 순간
그 이하는 텔레그램 서버에서 **영구 삭제**되어 다른 폴러에게 다시 오지 않는다.

봇을 공유한 채 Heimdallr가 폴링했다면:
- HermesCall 앞으로 온 `/add` `/list`가 **Heimdallr에게 먼저 잡혀 사라진다**
- 항상이 아니라 **경쟁 상태**라 "가끔 씹힌다"로 보인다
- 재현이 안 되고 로그에도 에러가 없다

→ `RECEIVING_METHODS`를 따로 두고 **전용 봇이 아니면 클라이언트 안에서 막았다.**
`sendMessage`는 상태를 소비하지 않으므로 공유 봇으로도 안전하다 —
**분리 전에도 알림은 계속 나가고 수신만 막힌다.** 기능을 통째로 세우지 않는 게 요점이다.

## 설계 판단

**웹훅은 분리 후에도 열지 않았다.** 사용자가 "setWebhook을 가능하게 하려면?"이라고 물었고,
분리됐으니 기술적으로는 가능하다고 답했다. 그래도 열지 않은 이유:
- 이 프로젝트는 공개 URL이 필요 없다(폴링으로 충분)
- 필요도 없는 기능 때문에 남의 봇을 죽일 경로를 남길 이유가 없다
- **LLM 분석이 10~30초 걸리는데 Vercel 서버리스는 10초(Hobby)/60초(Pro)에서 잘린다.**
  웹훅으로 받으면 즉시 200 응답 후 백그라운드 처리가 필요한데 서버리스는 응답 직후
  프로세스를 죽인다 — 큐나 별도 워커가 있어야 한다. 폴링에는 그 문제가 없다.

**offset을 우리 DB에 저장하지 않는다.** 처음엔 `kv_state` 테이블을 쓰려 했는데
테이블이 없었고, 확인해보니 **텔레그램이 이미 기억한다.** DDL 없이 해결됐다.
단 **처리 후에** 확정해야 한다 — 먼저 확정하면 중간에 죽는 순간 메시지가 조용히 사라진다.
지금은 at-least-once(죽으면 다시 온다)다.

**들어온 메시지는 데이터이지 명령이 아니다.** 텍스트는 종목을 찾는 데만 쓰고,
안에 어떤 지시가 적혀 있어도 실행하지 않는다. 회신은 우리가 만든 형식뿐이고
**사용자 텍스트를 그대로 되돌리지 않는다**(에코 회피).
`test_message_text_is_data_not_instruction` / `test_reply_does_not_echo_user_text`가 고정한다.

**모르는 chat은 조용히 무시한다.** 응답하면 봇의 존재와 동작을 알려주는 셈이고,
분석은 건당 실제 비용이 든다.

**애매하면 단정하지 않는다.** "한미" → 한미반도체·한미약품 후보를 제시하고 고르게 한다.
하나를 골라 단정하면 엉뚱한 종목을 분석하게 된다.

**LLM은 기존 분석이 없을 때만 호출한다.** 같은 종목을 여러 번 물어도 비용이 늘지 않는다.

## 해석 로직에서 잡은 버그 2건

**① 부분 일치가 한 방향뿐이었다.** `이름 ⊂ 문장`("삼성전자 어때?")만 처리하고
`질의 ⊂ 이름`("한미" → 한미반도체)은 통째로 안 잡혔다. 에러 없이 "그런 종목 없다"가 된다.

**② 두 방향은 길이 선호가 반대다.**
- `contains`(이름 ⊂ 문장): **긴** 이름이 구체적 — "한화에어로스페이스 실적"에서 '한화'도
  걸리지만 답은 한화에어로스페이스다
- `partial`(질의 ⊂ 이름): **짧은** 이름이 질의에 가깝다 — "한미"에는 한미약품이 먼저

한쪽 기준으로 뭉뚱그리면 둘 중 하나가 반드시 엉뚱한 종목을 1순위로 올린다.

## 상시 실행

`--watch`는 롱폴링 루프인데, 처음엔 **출력이 통째로 안 보였다.** 파이프로 넘기면
stdout이 블록 버퍼링되어 "돌고 있는지 죽었는지 구분할 수 없다."
→ 매 출력마다 flush하고, 5회(약 2분)마다 "대기 중" 신호를 찍는다.

`.github/workflows/telegram_listen.yml`을 만들었다(5분 주기 `--once`).

- **`--watch`가 아니라 `--once`를 주기 실행한다.** 잡 안 sleep도 과금된다(PRD §10.1).
- **`concurrency` 그룹 필수.** getUpdates는 소비라 두 잡이 겹치면 서로 메시지를 빼앗는다.
- ⚠ **로컬 `--watch`와 워크플로를 동시에 켜면 응답이 한쪽으로만 간다.** 같은 T44 문제를
  스스로에게 저지르는 셈이다. 워크플로를 켜면 로컬 watch는 꺼야 한다.

## ★ 근본 원인 — `parse_mode`를 안 쓰고 있었다 (T45)

숫자를 `f"{v:>8}"`로 정렬해 놓고도 폰에서는 자릿수가 흩어졌다.
**텔레그램 기본 폰트가 비례폭이라 공백 정렬이 아예 통하지 않는다.**
데스크톱에서는 그럭저럭 맞아 보여서 넘어가기 쉬운 종류였다.

→ `send_message(parse_mode="HTML")`을 기본으로 하고 숫자 표를 전부 `<pre>`로 옮겼다.
`<pre>`만 고정폭으로 렌더된다.

### 같이 걸린 것 셋

**① `len()`으로 폭을 재면 한글이 절반으로 계산된다.**
"32자 이내"로 맞췄는데 실제로는 두 배였다. 한글·이모지는 모노스페이스에서 **2칸**이다.
실측: 삼성전자 제품 줄이 `len` 69자 → 실제 **138칸**, 폰에서 6줄로 접혔다.
→ `display_width()`(ascii 1 · 나머지 2) + `clip()`.

**② HTML 모드에서 `<`는 태그로 해석돼 발송이 400으로 죽는다.**
`F.PER 10.5 <컨센 기준>`이라고 썼더니 텔레그램이 파싱에 실패했다.
`<pre>` 안이라고 예외가 아니다. 종목명에 `&`가 들어오는 경우도 실재한다.
→ `esc()` 추가 + 태그 화이트리스트를 테스트로 고정.

**③ 한 표에 단위를 섞으면 표가 표로 안 보인다.**
`1,714,995억`과 `135억`이 한 열에 있으면 눈이 자릿수를 못 센다.
→ `pick_unit()`이 계열 최댓값 기준으로 단위 하나를 고른다.

## 못 한 것 — 제품별 비중

**현재 데이터로 불가능하다.** `krx_universe.products`는 이름 나열뿐이다:

```
'라면,스낵,유제품,장유,식용유,사료,향신료,건강음료(루이보스 티) 제조,도매'
```

비중(%)은 DART 사업보고서 §II '매출 실적' 표에 있고, 회사마다 표 형식이 달라
P4 잠정실적 파서 수준의 **별도 수집기**가 필요하다.
→ **없는 값을 지어내지 않고** 이름 3개만 보여주며 "비중 미수집"이라고 밝힌다.
