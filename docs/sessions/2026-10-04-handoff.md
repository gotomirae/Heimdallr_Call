## 4. LLM 오류 원인과 최종 방어

1. 싸이맥스 요청 10의 원래 실패는 Anthropic의 **compiled grammar too large** 400이었다. PC 작업 `HeimdallrDashboardAnalysis`가 이 작업공간의 pythonw로 실행 중인 경로를 확인했다.
2. 12개 문자열 전송은 컴파일을 통과했지만 문자열 내부 JSON 복원에 실패했다. 52개 평탄 필드도 컴파일에서 거절됐다. 무료 토큰 계수 성공은 컴파일 성공의 증거가 아니다.
3. 최종 전송은 작은 **typed cells 목록 + 별도 필수 confidence enum**이다. Canonical 분석 항목을 줄이지 않고 경로·인덱스·타입·필수 항목·열거값·관련 목록 길이를 복원/검증한다. 중복·누락·인덱스 공백·상충 신뢰도는 실패다.
4. 전송 자리표시자 0/false는 미사용 슬롯에만 존재하며 보고서 값으로 채우지 않는다. 파싱 실패도 usage를 보존해 발생 비용을 누락하지 않는다. 모델/Provider를 조용히 바꾸지 않는다.
5. 실제 cells 응답의 confidence는 빈 문자열이었다. 원문에 명시된 **‘확신도는 낮게 둔다’**를 low로 정규화해 동일 응답을 재생했다. 명시 문구가 없거나 모순·부정문이면 추정해 채우지 않는다. 이후 신뢰도는 별도 필수 strict enum으로 강제한다.
6. 검증된 12개 항목을 저장 후 두 번 재조회했다. Canonical 오류 0·invalid=false·last_attempt success, 요청 10 completed. 입력에 없는 사실 숫자 19개는 제거/미확인 표기했다.
7. 이번 유료 검증은 웹검색 OFF였다. 검색을 한 것처럼 읽히는 표현을 제공 자료 기준으로 바로잡고 미실행/발췌 한계를 표시했다. 수주 발췌 미확인은 계약 부재의 증거가 아니다.
8. 마지막 root confidence 필수 enum 경로는 회귀 재생으로 검증했다. 그 변경 후 별도의 유료 생성을 추가로 실행하지 않았다. 실제 생성 성공과 후속 정규화/회귀 검증을 구분한다.
