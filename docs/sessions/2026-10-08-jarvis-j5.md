## 구현

- 실행 출력의 인증 오류 또는 CLAUDE_EXIT 직후 로그인 없음은 failed 대신 pending/CLAUDE_LOGIN_REQUIRED/30분 retry_after. 기존 사용량 재시도 상한 유지. 로그인 없음은 claim 전에 종료한다.
- SQLite auth 상태로 장애 시작/마지막 KST 알림일 유지. 30분 지속 시 Heimdallr 봇 개인 채팅으로 하루 1회 재로그인 안내. 발송 전에 날짜 예약, 결과 불확실 시 같은 날 재발송하지 않음. 정상 인증 실행은 장애 시작만 초기화하고 그날 알림 이력은 보존한다.
- subscription_cli_env가 optional_env로 정리한 구독 CLAUDE_CODE_OAUTH_TOKEN만 추가 허용. API 과금 키·endpoint/provider 차단 유지. 로그인 probe·설치기도 oauth_token을 같은 계약으로 허용. 실제 토큰은 생성·저장·출력하지 않았다.
- 실행기 WORK_ROOT의 직접 environ 읽기도 중앙 optional_env로 변경했다.

## 실측·검증

- 실제 CLI에 무효 fixture 토큰으로 auth status만 실행: exit0/loggedIn=true/authMethod=oauth_token. 모델 호출·실제 토큰·계정 정보 출력 없음. 따라서 실행 인증 실패 기록은 표면 loggedIn만으로 초기화하지 않도록 보강했다.
- 현재 기존 Telegram 설정은 정확한 Heimdallr 봇 ID8933940541/개인 채팅이다(getChat 읽기). 전용 이름 env가 비어 있어도 기존 TelegramClient 설정을 사용하되 봇 숫자 ID와 private를 강제한다. 시험 알림 0건.
- 기존 예약 작업은 그대로 유지한다. 실행기 상태 및 최종 회귀 수치는 아래 완료 기록으로 보완한다.
- 최초 집중71 passed, 전체1,313 passed/2 skipped/3 network deselected. 이후 전용 봇·개인 채팅 방어3건을 추가했으므로 최종 회귀는 재실행한다.

## 한계

로그인 소실은 통제 재생으로 검증했다. 실제 구독을 로그아웃하거나 하루 동안 장애를 유지하는 실험은 하지 않았다. OAuth 토큰 지원은 실제 CLI 메서드 표기와 환경 계약을 검증했고 사용자 구독 setup-token 실물 발급·모델 호출은 하지 않았다. 기존 A1은 이미 완료되어 새 Notion 페이지·재실행·시험 요청을 만들지 않았다.
