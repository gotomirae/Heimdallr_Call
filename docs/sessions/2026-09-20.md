## 변경

- Telegram 기업명·코드 단독 입력은 짧은 실적 요약 대신 접수 상태·시작/완료 예상 시간을 전송하고 메시지 ID를 저장한다. 접수 메시지 발송이 실패하면 Telegram update를 확정하지 않아 다음 주기에 다시 시도한다. `claim`과 산업·기업·Notion·검증·사용량 중단 단계에서 동일 메시지를 갱신한다. 5분 넘게 시작하지 않으면 지연·재시도를 표시한다. `/status`는 새 분석을 시작하지 않고 최근 작업·단계·갱신 시각을 보여 준다. 완료 링크는 기존처럼 새 메시지로 발송한다.
- 새 Windows 1분 Telegram 수신기 `telegram_bridge/listener_once.py`와 설치 스크립트를 추가했다. GitHub 워크플로는 코드상 예약·실행이 제거되도록 준비했다. 로컬 `pending`의 Codex 깨우기는 claim이 없으면 5분 후 재시도한다.
- Kairos 원본·설치 스킬에 분기 실적 그래프+표, 네이버·StockEasy 종목 링크, 공개 근거로 답하는 주담 질문 최소 5개, 단계별 진행 갱신을 동기화했다. 스킬 검사 **2/2 유효**, 양쪽 파일 해시 일치.
- 기존 [비엠티 Notion 분석](https://app.notion.com/p/3e09c770aa61813f8cb3c4374faf806a)에 핵심 지표 표, DART 분기 숫자 5개 분기의 HTML 그래프, 주가 링크, 공개자료 근거의 주담 Q&A **8개**를 추가했다. Notion 재조회에서 그래프 embed·두 주가 링크·Q&A 1~8을 확인했다. 실제 주담 통화는 미실시로 구분했다.
