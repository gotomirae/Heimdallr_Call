# 2026-10-08 수주기업 선분류·분기 조사 장부

요청: 수주기업을 먼저 분류하고 이 기업의 수주잔고·분기 신규수주·잔고 QoQ를 조사해 대시보드에 반영한다. 전 기업 세 항목 확보를 완료했다고 선언하지 않는다.

## 실제 분류와 저장

시총 1,000억원 이상·제외 아닌 **1,206기업**, 발췌 **12,051행**을 range 페이징으로 읽었다. 캐시 원문 **4,464보고서**의 수주 절 전체를 재생해 사업 형태를 금액 단위 파싱과 독립적으로 조사했다. 최종 **수주 확인 446 / 확인 필요 748 / 비수주 명시 12**. 최초 481개에서 “대량생산이라 수주총액 의미가 미미하여 기재를 생략” 같은 모호한 문구를 제외해 35개를 확인 필요로 옮겼다. 비공개·영업비밀·보안 근거와 단순 기재 생략을 구분한다.

운영 **1,201기업 장부·4,464원문 분류** 저장 성공. 실제 공시 앵커가 없는 5기업은 가짜 행 없이 UI 확인 필요로 유지한다. 저장 시 기존 DART·IR·기타 sections를 보존하고 재수집도 IR와 조사 장부를 보존한다.

현재 최신 기간·동일 범위에서 세 항목 모두 측정된 기업은 **16개**다. 부분 사업 범위를 포함하며 회사 전체 신규수주 확보 16개라는 뜻이 아니다. 수주 확인 기업 중 **430개**는 최신 세 항목 미확보다. 기존 역사 자료의 세 항목 확보 수를 최신 분기 확보 수로 바꾸지 않았다. 최신 회사별 CSV와 정확한 범위별 16기업 집계는 아래 파일에 저장했다.

- `assets/2026-10-08-order-company-audit.csv`: 전체 1,206기업, 분류·최신 기간·범위·단위·세 값·미확보 이유·원문.
- `assets/2026-10-08-order-company-summary.json`: 최종 분류·IR 조사·최신 동시 측정 범위별 집계.
- `assets/2026-10-08-kind-ir-summary.json`: 실제 전체 KIND 조사 요약.

## 공식 IR 조사

초기 수주 후보 481기업 전체를 2024-01-01~2026-10-08 KIND 공식 제출 자료로 조회했다. 실제 목록 **3,611행·37페이지**, 대상 일치 **1,161제출 행·175기업**, 중복 제거 후 **926PDF 읽기 성공 / 실패1**. 수주 후보 **202문서·61기업**, 텍스트 없는 PDF **272개**. 최종 수주 확인 446기업에 한정하면 **810읽은 문서·199후보 문서·59후보 기업·실패1**이다. 조사 메타데이터는 최종 수주 확인 **446/446**에 부착했다. 후보가 있어도 기간·범위·단위를 대조하기 전 수치를 승인하지 않았다.

실패: 샘씨엔에스 252990, 2024-09-23 `[샘씨엔에스] IR BOOK(2024년)-1.pdf`의 공개 KIND URL이 PDF가 아닌 응답을 반환했다. 실패를 장부에서 숨기지 않았다. KIND 제출이 없는 기업은 회사 자료실 후속 조사 대상이다.

에스티팜 최근 IR은 잔고를 제시하나 신규수주 직접값이 확인되지 않았다. 피엔티 자료의 연간 신규수주에는 `당기잔고−전기잔고+당기매출액` 산출 주석이 있어 이를 분기 총 신규수주로 만들지 않았다. 원문 미검출은 회사가 미공개했다는 확정 사유로 쓰지 않는다.

## IPARK현대산업개발 추가 실측

공식 자료실 https://ipark-dvp.com/ko/ir/information/materials 에서 공개 storage key 폼으로 **24Q1~26Q2 10PDF**를 다운로드했다. 각 파일 해시·실제 수주 페이지·억원 단위를 확인하고 전체 수주 페이지를 렌더링 대조했다. 원문 페이지가 이미지인 경우 직접 읽었다. 동일 자료실 URL 아래 파일별 key를 캐시 키에 포함해 다른 분기 PDF 재사용을 막았다. HTML 자료실 URL에 가짜 `#page`를 붙이지 않는다.

검증 사실 **11개 저장·정확 재조회**. 2026Q2 잔고 **329,873억원**, 반기 신규 **12,997억원**, Q1 신규 **3,091억원**, Q2 단독 **12,997−3,091=9,906억원**. QoQ **(329873/328506−1)×100=+0.41612634168%**. 실제 UI **329,873 / 9,906 / +0.42%** 확인했다.

24Q1 내부관리회계, 24Q2~25Q4 발표 계열, 2026 비교표 계열을 분리했다. 24Q1 누적17,206과 24Q2 누적16,944를 차감하지 않는다. 26Q2 자료의 25H1 비교28,549는 당초28,548과 **1억원** 다르므로 발표 계열을 섞지 않는다. 2026 자료에 실린 25Q4 잔고331,603은 현 비교계열의 Q1 QoQ 앵커로 따로 저장했다. DART 회사 공시 합계 잔고222,936.15억원과 IR 주택·토목·건축 합계329,873억원은 다른 범위로 보존한다.

## 화면과 자동 갱신

`/orders`에 수주기업 탭을 추가했다. 상태·기업명/코드/섹터 검색·세 항목 미확보 필터, 분류 원문·금액 원문·범위별 최신 값·추가 조사 사유·IR 조사 수를 표시한다. 처음50기업과 추가50기업 표시로 초기 DOM을 제한하고 각 종목의 실제 수주 그래프로 연결한다. 기존 그래프는 범위·통화를 분리하고 최신 완전 범위를 먼저 표시한다.

첫 실제 화면에서 장부 JSON 전체 필터의 두 번째 range 조회가 Supabase statement_timeout 57014로 실패했다. 기존 `(code,fiscal_year,fiscal_quarter)` 인덱스를 활용하도록 **100종목씩·동시3묶음** 조회로 수정했다. 새 테이블·DDL은 추가하지 않았다. 수정 후 실제 `/orders` **HTTP200·1,345ms**와 1,206기업/분류/세 항목 수·IPARK 값을 확인했다. 각 묶음은 range 페이징을 유지한다.

기존 평일02:37KST `order_disclosure` 수집 뒤 장부 갱신 job을 연결했다. canonical 대시보드 순수 함수를 Node/jiti로 재사용하며 jiti를 devDependency에 선언하고 CI에 Node20을 설치한다. 새 요청·유료 LLM·Telegram 리서치·Notion 시험 페이지는 만들지 않았다.
