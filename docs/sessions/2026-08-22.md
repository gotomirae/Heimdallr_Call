### 1. 게이트에 G4(OPM YoY 상승) 추가 — 사용자 지시

발단은 화면 문구였다. 사용자가 "게이트 통과 = 매출/영업이익 YoY 가속 **+ OPM 상승**"으로
표시해 달라고 했는데, **게이트에 OPM 조건이 없었다.** `F4_OPM_DELTA_MIN_PP = 1.0`은
정의만 되고 어디서도 쓰이지 않는 죽은 상수였다(전수 검색 2건 — constants.py와 PRD뿐).

라벨만 바꾸면 화면이 거짓말을 하게 되므로(T83) 사용자에게 확인 → **게이트를 실제로 고치기로 결정.**

- `G4: opm_yoy_delta(t) > 0` — **방향만 본다.** 크기는 스코어 B1이 이미 점수로 잰다.
  임계값을 1.0%p로 두면 "조금 오른" 종목이 통째로 탈락한다.
- 결측은 `False`가 아니라 `None`(판정 불가) — G1·G2와 같은 규칙.
- `G4_OPM_DELTA_MIN_PP = 0.0`으로 죽은 상수 `F4_*`를 대체.

| | 이전 | 이후 |

A3는 **대상이 바뀌었다** — TTM 매출 → TTM 영업이익. `run.py`의 `FUND_COLUMNS`에
`ttm_op` 추가(컬럼은 이미 DB에 있었다). 안 넘겼으면 A3가 전 종목 None이 되고,
A축은 나머지 항목으로 '측정됨'이라 분모에서 빠지지도 않아 **에러 없이 4점씩 조용히 감점**됐을 것이다.

증가율 보너스는 `TTM_op(t−1) > 0`일 때만 준다 — 적자 구간에서 %를 만들면
적자 축소가 수백 % '성장'으로 둔갑한다.

반영한 곳 6군데: `constants.py` · `score.py` · `types.ts` · `glossary.ts` ·
`constants.json`(생성물, 재생성) · PRD 두 곳(§4.2 표 + 부록 A).

### 3. 발굴 목록 — 사용자 지시 4건

- **게이트 설명**을 G4 포함으로 고쳤다. "성장 가속 = 매출액과 영업이익 YoY 성장률이 전분기보다 상승" 한 줄 추가.
- **정렬을 필터와 무관하게 고정**: 최신 분기 → 스코어 → 영업이익 YoY → 시총.
  등급 우선 정렬을 버렸다 — 등급은 스코어×반영도의 파생값이라 1순위로 두면
  "스코어가 더 높은데 아래에 있는" 줄이 생긴다.
- **등급·섹터 복수 선택**(`MultiSelect.tsx`). `<select multiple>`은 쓰지 않았다 —
  Ctrl을 모르면 클릭할 때마다 앞 선택이 지워져 기능이 있는데 없는 것처럼 보인다.
  **빈 선택 = 전체**.
- **매출 YoY · 영업익 YoY · OPM YoY 열 추가.** `screen_results`에 YoY 원자료가 없어
  평가 분기의 `quarterly_fundamentals`를 따로 읽어 붙인다. 종목마다 평가 분기가
  다르므로(T36) 존재하는 분기를 전부 읽는다 — 최신 한 분기만 읽으면 일부 행만 조용히 빈다.

## 도중에 발견한 것 (전부 traps.md에 기록)

- **T85** LLM 분석 읽기 키 4곳이 저장 키와 달라 **항상 비어 있었다.** 데이터는 316행 중
  310건이 멀쩡했다 — 방어 코드가 결측과 **오타를 똑같이 삼켰다.**
- **T86** 복원 플래그를 `useRef`로 두면 저장 effect가 같은 커밋에서 기본값을 덮어쓴다.
  StrictMode 이중 실행이 확정타. → `useState`로 교체.
- **T87** 값은 `%`, **차이는 `%p`**. 그리고 표시 자릿수보다 작은 차이로 판정이 뒤집혔다
  (33.9% → 33.9%인데 '미달'). → `EPSILON_PP = 0.05`.
- **T88** 분기가 넘어가면 직전 분기 분석이 화면에서 사라진다 — **63종목**이 그 상태였고,
  하필 그 63종목이 **검증 가능한 유일한 대상**이었다.
- **T89** 부호 검사가 인사이트 ①에만 있고 ②에는 없어 **두 조언이 서로 어긋났다**
