## 1. 실적 가속의 정의를 게이트에 반영 (T60)

**정의(확정)**: 매출액 성장률과 영업이익 성장률이 **둘 다** YoY로 가속한 종목.

| | 이전 | 이후 |
|---|---|---|
| G1 매출 | `rev_yoy(t) > rev_yoy(t−1)` AND `> 0` | 그대로 |
| G2 영업익 | 흑자 AND `op_yoy(t) > 0` | 흑자 AND **`op_yoy(t) > op_yoy(t−1)`** AND `> 0` |

`> 0`을 함께 요구하는 이유: 빼면 **영업이익 −30% → −10%가 '가속'으로 통과한다.**
G1이 이미 `가속 AND 양(+)` 둘 다 보므로 대칭을 맞췄다.

**결정을 사용자에게 물은 이유** — 단순 구현이 흑전을 통째로 죽이기 때문이다.
`op_yoy`는 부호전환 구간에서 애초에 `None`이라(T25), None을 False로 뭉개면:

```
현재 통과 343
  ├ 영업이익도 가속        182
  ├ 가속 아님               69   ← 의도한 탈락
  └ op_yoy=None             92   ← 전부 부호전환. 당분기 흑전 53 포함  ★
```

흑전은 이익 가속의 **가장 강한 형태**인데 정확히 그것만 사라진다.
사용자가 "게이트에 추가 + 흑전은 통과 인정"을 선택했다.

```python
elif data.op_status_label == "흑전":
    result.g2 = True                              # %는 못 구하지만 명백하다
elif data.op_yoy_t is None or data.op_yoy_t1 is None:
    result.g2 = None                              # ★ 탈락이 아니라 판정 불가
else:
    result.g2 = data.op_yoy_t > data.op_yoy_t1 and data.op_yoy_t > 0
```

`적자축소`는 별도 처리가 필요 없었다 — `op_t <= 0`이라 "흑자" 요건에서 이미 걸린다.

**실측(재계산 후 저장 완료)**

```
통과      343 → 238        판정 불가 91        흑전 통과 76
등급      ★25 ○42 △18 ·126 ✕27
발송 대상  80 → 67
```

`src/screener/run.py`에 **`op_yoy_t1` 배선을 빠뜨리면 G2가 전 종목 None**이 되어
발굴 결과가 통째로 빈다. 주석으로 못 박았다.

## 2. ★★ 배포 대시보드가 이틀 전 데이터를 보여주고 있었다 (T59)

게이트를 고치고 DB가 67이 됐는데 화면은 계속 **80**이었다.

| 경로 | 값 |
|---|---|
| DB (service key) | 67 ✓ |
| DB (anon key + 페이징) | 67 ✓ |
| node에서 supabase-js 직접 재현 | 67 ✓ |
| 로컬 `next start` | **80** ✗ |
| **배포 사이트** (`X-Vercel-Cache: MISS`) | **80** ✗ |

쿼리 로직은 멀쩡했다. 범인은 `.next/cache/fetch-cache`의 **8월 15일자 파일 44개**였다.

`export const dynamic = "force-dynamic"`은 **페이지 렌더를 매번 다시 할 뿐**,
supabase-js가 부르는 `fetch`까지 막지 않는다. Next는 응답을 디스크에 남기고
**Vercel은 그 빌드 캐시를 배포 사이에 복원한다** — 그래서 배포해도 안 고쳐진다.

HTTP 200 · 화면 정상 · 에러 로그 없음 · CDN도 MISS. **숫자만 낡는다.**

→ `NO_STORE_OPTIONS`를 만들어 **`createClient` 호출 3곳 전부**에 적용했다.
페이지용 anon만 고치면 `/api/cost`(service_role)와
`/api/telegram/lookup`(HermesCall이 부른다)이 그대로 낡는다.

**검증은 캐시를 지우고 하면 안 된다.** 캐시 파일 9개가 **남아 있는 상태에서**
67이 나오고 새 캐시도 안 늘어나는 것을 확인했다.
`tests/test_workflows.py`가 `NO_STORE_OPTIONS` 없는 `createClient`를 막는다.

## 5. 화면 개편

### 발굴 목록 (`/`)

열을 요청대로 바꿨다 — 실측 렌더 확인:

```
섹터|종목명|등급|분기|스코어|반영도|시총|최근 5일
```

- `thead`에 `sticky top-0` — 아래로 스크롤해도 머리글이 남는다
- **등급 순 정렬** — 실측 238행이 `★25 → ○42 → △18 → ·126 → ✕27` 순서로 나온다
  (같은 등급 안에서는 스코어 내림차순. 안 그러면 ★ 25종목의 차례가 매번 달라진다)
- 맨 위에 **실적 가속의 정의**를 박아 뒀다 — "왜 이 종목들이 여기 있나"의 답이다

### 종목 상세 (`/stock/[code]`)

**차트 8분기 → 9분기.** 라인 구성:

| 요소 | 의미 |
|---|---|
| 초록 굵은 실선 + 값 라벨 | **영업이익 YoY** (주인공) |
| 주황 실선 + 값 라벨 | 매출 YoY |
| 회색 점선 | TTM 매출 |
| 보라 점선 | 분기말 주가 |

성장률 **숫자를 라인 위에 직접** 찍는다 — 오른쪽 축만 있으면 눈이 축과 점 사이를
왕복해야 해서 "몇 %에서 몇 %로 갔는지"가 안 읽힌다. 결측 분기는 라벨을 **안 찍는다**
(0으로 보이면 안 된다).

차트 아래에 TTM의 의미를 설명하고, **측정된 분기 수를 밝힌다**:

```
측정된 분기 — 영업이익 YoY 0/9 · 매출 YoY 6/9 · 주가 0/9.
빠진 구간은 흑자↔적자 전환이라 성장률(%)을 계산할 수 없는 분기다(0%가 아니다).
```

(실측 011170 롯데케미칼 — 흑전 종목이라 초록 선이 아예 안 그려진다.
안 밝히면 "0% 근처에 붙어 있다"로 잘못 읽힌다.)

**밸류에이션 재배치.** ① 최근 4개 분기 순이익 기준 PER → ② 향후 4개 분기 선행 PER.
**후행 PER은 화면에서 뺐다**(실측 노출 0건). 나란히 두면 큰 쪽에 눈이 가서
"이미 비싸다"는 정반대 결론이 나온다. 각 항목에 무엇을 재는지와 분모 근거를 붙였다.

실측 004000 롯데정밀화학: ① **6.0배** (분모 2,011억 · 2026.2Q까지 4분기 누적) ·
② **—** (연간 컨센서스 없음 — 이유를 화면에 밝힌다).

선행 PER 계산은 `src/notify/run.py`에만 있던 것을 `dashboard/lib/valuation.ts`로 이식했다.
**같은 종목에서 텔레그램과 화면이 다른 배수를 말하면 신뢰가 통째로 깨진다** — 양쪽 파일에
서로를 가리키는 주석을 달았다.
