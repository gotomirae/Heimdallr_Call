# ADR 10 — LLM 사실 숫자는 입력 참조로만 전달한다

날짜: 2026-08-30

## 결정

**상태: canary 전용 실험 — 운영 기본 요청에는 승격하지 않는다.**

실험 LLM 요청은 과거·현재 사실 숫자를 `[[F001:+595.1억원]]`처럼 입력에 표시한다.
모델은 사실 서술에서 전체 표식 `[[F001:+595.1억원]]`을 그대로 복사하거나 `[[F001]]`
참조를 반환한다. 저장 전 결정론 코드가 두 형식을 입력의 정확한 표시값으로 복원한다.

- 기존 화면과 `analyses.payload` 스키마는 바꾸지 않는다.
- 입력에 없는 참조와 값이 바뀐 전체 표식은 저장 전에 차단한다.
- 참조 없이 직접 쓴 숫자는 기존 동일 단위 grounding gate에서 입력과 정확히 같거나 허용된
  표시 반올림인지 검사한다. 단위 환산과 새 계산은 계속 차단한다.
- 복원 뒤에는 기존 동일 단위 숫자 grounding gate를 다시 통과시킨다.
- 미래 시나리오 조건과 risk watch metric의 임계값은 투자 판단이므로 참조 대상에서 제외한다.
- 참조 계약이 없던 과거 request snapshot은 그대로 평가하며 소급 변환하지 않는다.

## 이유

실제 4-case canary에서 OpenAI와 Anthropic 모두 품질 통과 0/4였다. 주된 실패는 입력의
공시 숫자를 모델이 억원·조원으로 환산하거나 새 비율과 차액을 계산한 것이었다. 저장
gate는 오염을 막았지만 결과를 생산하지 못했고, 출력 직전 숫자 자체감사 프롬프트는 같은
롯데정밀화학 replay에서 unsupported 6→8, 점수 65.00→63.57로 악화됐다(T124).

숫자 복사를 모델의 생성 과제로 남겨 두는 한 프롬프트 표현을 바꿔도 같은 오류가 반복된다.
참조와 결정론적 복원으로 숫자 표기를 프로그램 영역으로 옮기면 Provider와 무관하게 입력의
정확한 단위·반올림을 보존하면서 기존 사용자 화면을 유지할 수 있다.

첫 실제 Anthropic canary에서 모델은 축약 참조 대신 정확한 전체 표식을 **68회** 복사했다.
이를 축약 참조만 허용하는 해석기가 전부 거부했고, 직접 쓴 숫자 5개도 입력과 같거나 허용된
동일 단위 반올림이었다. 전체 표식의 ID와 값이 모두 입력과 일치할 때만 복원하도록 계약을
현실의 출력 형태에 맞췄다. 유일한 실제 미근거 계산값 `+4.2%p`는 모델에게 계산시키지 않고
Python이 OPM QoQ 변화로 입력에 제공한다.

두 번째 동일 canary에서는 unsupported factual number가 **0건**이 되어 숫자 경계의 목적은
달성했지만, 모델이 핵심 필드 11곳을 `placeholder`로 채워 전체 품질은 **26.43점**이었다.
따라서 이 ADR은 숫자 정확성 경계일 뿐 분석 품질이나 Provider 전환의 근거가 아니다.

세 번째 medium-effort canary는 filler 없이 길게 답했지만 전체 표식 54개 중 3개의 원문값을
억원으로 환산해 바꿨고, 직접 숫자까지 포함해 unsupported 5건으로 실패했다. **63.57점 ·
$0.094465**였으며 DB 쓰기는 0건이다. 세 번 모두 quality=false이므로 `analyze()` 운영 요청은
참조 없는 기존 계약을 유지한다. 구현과 raw artifact는 canary 연구용으로 보존한다.

## 되돌리면 무엇이 무너지는가

모델이 다시 사실 숫자를 직접 쓰게 되면 단위 환산·새 계산·부정확한 반올림이 구조화 JSON을
정상 통과한다. 저장 gate가 차단하더라도 유료 호출은 이미 끝났으므로 분석 성공률과 비용이
함께 악화된다. Provider별 프롬프트 순응도에 숫자 정확성을 맡기게 되어 동일 replay 비교도
다시 불안정해진다.
