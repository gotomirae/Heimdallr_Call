# ADR 39 · Telegram에서 Claude 분석·기업/산업 발표자료를 명시적 버튼으로 요청

날짜: 2026-10-09 · 상태: 채택 · PRD §8.7 K

## 무엇을

Codex 분석이 실제 Notion 저장·재조회·sent를 마친 Telegram 완료 메시지에 Claude 분석 요청 버튼을 제공한다. 원 요청 소유자가 전용 봇의 개인 채팅에서 누르면 기존 kairos_deck_requests의 mode=analysis로 접수한다. Claude 성공 후에는 PPT 요청 버튼을 제공하고 mode=deck으로 접수한다. 기존 JARVIS source=jarvis 자동 분석과 무발송 계약은 유지한다.

기업·산업 모두 기존 Claude 구독 실행기와 실제 Codex Notion·장부·sources를 사용한다. 산업 발표자료는 기업 20장 양식의 디자인을 보존하되 산업용 내용 매핑을 적용한다. 원래 사용자 분석 지침은 수정하지 않는다. PPTX와 PDF 미리보기를 원 분석의 대상 부모에 첨부하고, 기업/산업 루트·전체 블록·SHA256·동일 요청·최근 재조회 증거를 검증한 뒤 sent로 저장한다.

## 왜

Telegram 사용자는 Codex 결과를 확인한 뒤 Claude와 PPT 작업을 각각 선택하기를 요청했다. JARVIS 자동 sent 트리거는 Telegram 요청을 자동 실행하지 않으므로 명시적 버튼을 기존 큐에 연결해야 한다. 원 완료 메시지와 실제 Claude 완료 알림의 메시지 ID를 검증하여 다른 사용자·전달된 버튼·미완료 분석이 후속 작업을 접수하지 못하게 한다. DB의 기존 고유 인덱스로 연속 클릭·재생을 중복 생성하지 않는다.

접수 DB 실패는 Telegram offset을 확정하지 않는다. 접수가 이미 영속 저장된 뒤 callback 알림만 만료된 경우에는 큐를 보존하고 수신을 계속한다. 완료 발송은 예약 장부를 먼저 기록하며 모호한 전송은 자동 재발송하지 않는다.

## 되돌리면 무엇이 무너지는가

자동 생성으로 바꾸면 사용자가 요청한 단계별 선택이 사라진다. 기업 전용 저장 함수를 산업에 사용하면 산업 PPT가 기업 루트에 조용히 저장된다. 파일 생성 성공만 확인하면 Notion에 PPT 없는 작업도 완료로 표시된다. 원 사용자·메시지 검증을 제거하면 타인의 결과에서 비용이 드는 작업을 접수할 수 있다.
