# ADR 49 — 실적 시즌·16시 지표·Pro Codex와 과거분기 Batch 운영 설계

> **최신 우선: ADR50**. 사용자 후속요청으로 Batch API 예외를 철회하고 과거분기까지Pro전용,16시지표작업 한국휴일제외,종목포함 고정내용/해설/보고서 분석버튼전용으로 수정했다. 이 문서는 이전설계 이력이며 [ADR50](050-trading-day-indicators-pro-only-analysis.md)이 우선한다.

PRD Ref: §1, §7, §8.7, §9, §10, §11

- 날짜: 2026-11-01
- 상태: 사용자 요청을 반영한 차기 운영 설계. 코드·예약·UI·운영 DB 미적용.
- 이전: ADR26(Batch 장부·예산·멱등 계약)은 유지한다. ADR48의 필수 Claude 단계는 이 차기 설계에서 Codex 검수 단계로 대체한다. 기존 완료 결과는 재생성하지 않는다.

## 목적

분기실적 기반 국내 종목 발굴을 자동·수동으로 수행한다. 정량 선별은 Python,해석은 ChatGPT Pro로 로그인한 Codex,과거 분기의 비긴급 일괄 분석만 OpenAI Batch API를 사용한다. 투자수익 개선은 당시 신호와 실행가능 가격을 고정한 비용후 성과로 평가한다.

사용자는 매일18시 이후 확인하고 주말1시간을 사용한다. PC 상시 가동은 선택 사항이다.

## 스케줄

| 구간 | 대상 | 갱신 규칙 |
|---|---|---|
| 국내 실적 시즌 | DART 공시·잠정/확정 실적·새 중요공시 | 한국시간2시간마다 확인.00/02/04/06/08/10/12/14/16/18/20/22시,일12회 |
| 국내 실적 시즌 외 | 매크로 원자료·각종 지표·종목별 주가·수급·밸류에이션·PRI 등 | 매일 한국시간16시에 일일 작업1회 시작 |
| 국내 실적 시즌 외 | 종목 외 해설·산업/시장 보고서·전략 설명 등 | 버튼 클릭 시 자료 확인·필요 분석·게시 |
| 전 기간 | 종목 수동 분석 | 명시적 요청을 영속 큐에 접수,동일근거면 기존 결과 반환 |
| 별도 과거분기 작업 | 미분석 과거 종목·분기 | OpenAI Batch API로 제출·별도 결과회수 |

시즌 중에도 주가/지표는 일1회16시 기준을 기본으로 두며 공시 변화 이벤트가 실적/분석을 별도로 갱신한다. 비시즌 공시 확인은16시 일일 작업에 포함하고2시간 반복은 하지 않는다. 휴일/미발표 지표는 가장 최근 확정값과 실제 기준일을 표시하고 새로운 수치처럼 시각을 바꾸지 않는다.16시는 실행 시작시각이며 상류 지연과 처리시간 때문에 전체 완료시각 보장은 아니다. 변경 없는 원자료의 정상 확인시각과 실제 발표/가격 기준일은 별도다.

시즌 날짜는 기존 PRD §10.2 집중기간·정기보고서 구간을 포함하는 설정 달력으로 관리한다. 정확한 시작/종료일은 공시 달력과 비12월 결산 예외를 반영해 구현 시 명시한다. 법정 마감일을 고정 영업일로 추측하지 않는다. 늦은 정정/비정상 발표는16시 일일 확인 또는 수동 갱신으로 복구한다.

기존 SC3의30분 알림 목표는2시간 감지와 양립하지 않는다. 차기 목표는 정상 실행에서 공시 공개 후 다음2시간 확인까지+실제 수집/처리/발송 시간이다. Codex 해석 완료는 PC/구독 사용량에 따라 지연될 수 있어 정량 알림과 분리해 측정한다. 예약기의 실제 지연도 별도 기록한다.

## 화면 버튼

- `시장·매크로 해설 갱신`: 원자료는16시 자동 갱신,설명/투자 시사점은 클릭할 때 갱신.
- `산업 분석 갱신`: 현재 선택 산업의 근거 변화 확인과 해석 요청.
- `전략·시즌 전망 갱신`: 최신 고정 신호·기존 성과·촉매를 근거로 설명 갱신. 과거 원본 전략/성과 장부는 덮어쓰지 않는다.
- `종목 분석`: 기업명·6자리코드의 자동대상 외 요청도 허용. 같은 근거는 재사용.
- `재분석`: 명시적 강제재검토 사유를 남겨 동일근거 중복차단의 의도적 예외를 기록.
- `PPT 만들기`: 검증·게시 완료된 원고/표/차트로 생성. 자동 생성하지 않는다.

버튼은 authenticated private queue로 접수하고 상태/마지막 완료/원자료 기준일을 보여준다. 공개 방문자의 무제한 생성은 허용하지 않는다. 중복클릭은 같은 작업을 반환한다. 버튼 클릭 자체가 원자료가 같아도 모델을 반드시 새로 호출한다는 뜻은 아니다. 종목 외 데이터 수치도16시 자동 갱신 대상이며 종목 외 해설은 버튼 갱신 대상이라는 해석이다.

## 분석 재사용·통합

- 같은 code/분기/분석 단계/근거 hash/요청계약·버전이면 기존 성공 분석을 반환한다. 수치만 같아도 새 중요공시나 원문이 바뀌면 변화로 판정한다.
- 재분석 조건은 잠정→확정,중요 신규 공시,명시적 수동 요청이다. 근거 변화 없는 정기 재호출은 하지 않는다.
- 주가만 바뀌면 Python이 밸류에이션·PRI를 갱신하고 분석 가격기준일을 표시한다. 가격기반 파생치를 갱신해도 기업 원고 전체를 새로 생성하지 않는다.
- Codex 작성→별도 검수 단계→Python 수치/단위/기간/출처 검증→게시→전체 재조회·해시 확인 순서로 통합한다. 필수 Claude 호출·Claude 로그인 대기를 없앤다.
- 기존 전체 양식·원본자료·최근3개월 발행일 정책·gap별 검색/분석 시도·반대논거·출처 검증은 유지한다. 작성/검수 상태·실파일 증거를 구분하며 동일모델 검수를 독립모델 검증이라고 표시하지 않는다.
- 과거분기 Batch 원고도 동일한 구조화 검증과 필요한 Codex 검수를 거쳐 게시한다. 과거 판단 재생용 자료는 해당 당시 공개 자료만 사용하고 사후 설명과 구별한다.
- PPT는 요청한 경우에만 이미 검증된 최종 원고를 재사용한다.

## 구독 사용량·무호출 원칙

Python이 큐·재개시각을 확인한다. 빈 큐나 reset 전 사용량 대기에 Codex를 호출하지 않는다. 동시실행 제어·상태 CAS·프로세스 종료 확인을 보존한다. 한도 도달 시 동일 요청ID/세션/원고·근거/진행단계/검증결과/재개시각을 체크포인트에 보존하고 가능해지면 이어서 실행한다.

Pro 한도 소진 작업은 API로 전환하지 않는다. 추가 Codex 크레딧 자동 구매를 하지 않는다. 과거분기 Batch 작업은 명시적으로 분류·접수된 별도 작업이며 구독 한도 소진의 대체 경로가 아니다. Batch 예산 소진도 예산 갱신/재지정까지 대기하며 일반 동기 API나 다른 provider로 폴백하지 않는다.

## Batch 예외와 비용

사용자의 최신 요청에 따라 기존 Pro 전용 권고에서 **과거분기 일괄분석만 OpenAI Batch API 별도 과금 예외**를 둔다. Anthropic API를 새 기본으로 사용하지 않는다. Pro 구독량으로 Batch API를 결제할 수 있다고 가정하지 않는다.

공식 Batch API는 지원 모델의 동기 API 대비50% 할인,24시간 처리창을 제공한다. 만료/부분완료/실패도 가능하므로 전건 성공을 약속하지 않는다. API키·지원모델·대상 건수·입출력 토큰·요율·비용한도를 제출 전에 확정한다. 구독용 모델명과 API 모델명을 동일하다고 추측하지 않는다.

ADR26의 종목/분기/단계/근거/계약 고유키,원자적 최악비용 예약,접수ID/custom_id 장부,submission_unknown 자동재접수 금지,결과 회수·비용정산 멱등,오래된 결과의 최신분석 덮어쓰기 방어를 유지한다. 실패분만 복구하며 성공분을 재결제하지 않는다. 기존 src.analysis.batch는50% 할인 Batch가 아니므로 이름만 보고 할인 적용으로 표시하지 않는다. 구현 상수는 constants.py 단일 출처로 유지하며 월 상한을 임의로 올리지 않는다.

지난 비용 검토의 가정을 유지하면 월비용=Pro 실제 구독료+기본 인프라25달러+과거분기 Batch 실제비용 B달러+PC전기료다.25달러는 추가프로젝트·compute·초과·부가상품을 제외한 예산이다. 환율1400원/달러·100W PC 하루4시간 월30일·전력300원/kWh 가정일 뿐 실제 계량/환율이 아니다.

| 과거분기 Batch 월비용 가정 | 기존Pro 제외 월운영비 | Pro200달러 포함 월합계 |
|---|---:|---:|
| 실행없음 B=0 |38600원|318600원|
| B=5달러 |45600원|325600원|
| B=10달러 |52600원|332600원|

Batch 할인은 API 토큰비용에 적용하며 구독·DB·전기료의50% 할인이 아니다. 정규 동기 토큰비용을 T달러로 계산했다면 같은 모델/같은 요청의 할인 대상 토큰비용은0.5T다. 선택모델·토큰·실패비용·캐시조건이 달라질 수 있어 지난 Anthropic 청구액을 곧바로 반으로 줄여 OpenAI Batch 예산으로 쓰지 않는다. 과거분기 보충비용을 매월 반복 발생하는 비용으로 자동 연간환산하지 않는다.

## 실행시간·PC

16시 지표 갱신과2시간 공시 확인은 클라우드 Python으로 수행한다. 구독 Codex 인증은 로컬에 유지한다. 매일18시 이후 검토에 맞춰 PC를17:30~21:30 켜는 방안을 유지하되 이는 제안시간이다. 주말1시간은 성과/반증/다음주 촉매 확인에 배분한다.

현재 Telegram 수신기는 로컬 전용이므로 PC off 동안 즉시접수·회신을 보장하지 않는다. 대시보드 영속 큐 접수와 구분한다. 상시 Telegram 접수가 필요하면 PC 상시 가동 또는 수신기 별도 호스팅 설계가 필요하다. 상시가동 전기료는 기존100W 가정에서21600원/월로4시간 가동보다18000원 높다.

## 적용 상태·검증

이번 변경은 계획/PRD 참조/세션 문서만 반영했다. 코드·버튼·cron·Windows 작업·DB/RPC·API키·실제 Batch 제출·Codex/Claude 실행 변경·게시/발송0건. 구현/배포 완료가 아니다. 할인율은 공식 문서 확인값이며 실제 운영 할인청구는 아직0건 검증이다.

후속 구현은 수집/분석 분리→시즌2시간·비시즌16시→수동갱신버튼→구독 Codex 작성/검수/게시→Batch 장부/예산/회수 순서다. 모듈 구현 전에 관련 PRD/함정을 다시 확인하고 과거데이터 재생에서 중복0·빈큐모델0·가격변화만모델0·reset전모델0·과거성공분재제출0·최신분석덮어쓰기0을 검증한다. 실제 Batch 비용 검증은 지원 모델과 범위/예산을 지정한 실행에서 수행한다.
