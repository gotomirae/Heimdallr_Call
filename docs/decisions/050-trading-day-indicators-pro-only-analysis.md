# ADR 50 — 거래일16시 동적지표·분석버튼·과거분기까지 Pro 전용

PRD Ref: §1, §7, §8.7, §9, §10, §11

- 날짜: 2026-11-01
- 상태: 구현·운영 main 배포·DB/cron·로컬 실행기 전환 확인. 운영 실측과 남은 한계는 세션 기록을 따른다.
- 우선순위: ADR49의 과거분기 OpenAI Batch API 예외와 비종목만 버튼갱신하는 규칙을 대체한다. ADR48 필수Claude 단계는 Codex 검수로 대체하는 방향을 유지한다. 기존 완료 결과/출처는 보존한다.

## 목적·갱신경계

분기실적 기반 국내 종목 발굴을 자동·수동으로 수행한다. 자동 발굴은 수집·구조화·정량 계산·선별·사실 알림을 뜻한다. 고정지표·내용·해설·보고서의 AI 분석/재작성/게시 갱신은 종목 여부와 관계없이 사용자의 분석 버튼으로만 시작한다. 새 중요공시가 있다고 보고서 전체를 자동 재작성하지 않는다.

| 작업 | 실행 조건 | 모델 호출 |
|---|---|---|
| 매크로·종목주가·수급 등 매일 변경되는 지표 | 한국시간16시,토/일·한국 공휴일 제외 | Python만 사용 |
| 주가연동 밸류에이션·PRI | 위 일일 가격 갱신 후 기존 검증 재무/가정으로 계산 | Python만 사용 |
| 실적시즌 공시 확인·구조화실적/정량선별·변화알림 | 기존 요청대로2시간마다 | Python만 사용 |
| 기업/산업/시장 고정지표·내용·해설·보고서 | 해당 화면의 `분석` 버튼 클릭 | Pro로그인 Codex |
| 과거분기 일괄분석 | `과거 분기 일괄 분석` 버튼에서 범위 지정·접수 | Pro로그인 Codex가 순차 처리 |
| PPT | 완료보고서의 `PPT 만들기` 요청 | 기존 원고 재사용·Pro 범위 |

16시 갱신은 시즌/비시즌 공통이다. 사용자 휴일제외 조건은16시 지표작업에 적용하고 기존2시간 공시확인에는 임의 확대하지 않는다. 한국 휴일은 공식 공휴일·대체공휴일·임시공휴일을 반영한 달력으로 판정한다. 국내 주가 원천의 추가 휴장 여부도 별도로 확인하고 없는 당일 가격을 만들지 않는다. 미국 매크로가 한국휴일에 바뀌어도 해당일 자동작업은 건너뛰고 다음 허용일에 최신 공개값을 확인한다.16시는 작업 시작시각이며 실제완료/원천발표/가격기준일을 분리한다.

## 원자료와 게시된 분석의 분리

DART 신규/정정 공시와 확정재무 원자료 수집은 자동발굴에 필요하므로 지속한다. 해당 원자료가 바뀌면 정량 게이트를 계산하고 기존 분석에 `새 공시 있음·분석 갱신 필요` 상태를 표시한다. 보고서의 고정지표·문장·표·판단은 버튼 전까지 저장본을 유지한다. 새 공시 원문과 기존 분석의 기준일은 함께 노출해 오래된 분석을 최신처럼 보이지 않게 한다.

PER/PBR/PRI 등 매일 변하는 파생수치는 기존 확인 재무/가정을 입력으로 Python이 다시 계산한다. 최신 수집재무와 분석에 채택된 재무가 다르면 각각의 분기·확정/잠정·기준일을 표시한다. 자동 지표패널이 갱신돼도 보고서 내부의 과거 숫자를 조용히 치환하지 않는다. 시장종가/일일지표 확인 때문에 Codex를 실행하지 않는다.

같은 종목·분기·근거·계약버전이면 분석 버튼을 눌러도 기존 성공 결과를 반환한다. 명시적 재분석 의도가 있으면 버튼 내 별도 재분석 선택/사유로 재검토를 접수한다. 잠정→확정·중요신규공시는 분석 필요조건이지만 최신요구에서 버튼 클릭을 대체하는 자동 생성조건은 아니다. Telegram 기업명/종목코드 요청은 분석 화면/선택 버튼을 제공하고 분석은 버튼 클릭으로 시작한다.

## Pro만 사용하는 과거분기 처리

OpenAI API·Anthropic API·Batch API를 사용하지 않는다. 기존 Batch50% 할인 예외는 철회한다. 과거분기 묶음은 API Batch 서비스가 아니라 로컬의 영속 작업큐다. Python이 이미 분석된 동일근거를 제외한 code/분기별 작업을 만들고 ChatGPT로 로그인한 Codex가1건씩 작성→검수→게시한다. 숫자계산/게이트/차트는 기존 Python을 사용한다.

수동현재분석/진행중요청을 과거보충보다 우선하고 과거작업은 남은사용량·실행시간이 있을 때만 이어서 처리한다. 한꺼번에 전종목·여러분기 전체 원고를 컨텍스트에 넣지 않는다. 최근/중요후보부터 진행하되 사용자가 지정한 범위를 장부에 보존하고 임의로 완료범위를 줄이지 않는다. 과거당시 판단 재생이면 당시공개자료만 사용하고 현재시점 사후설명과 구분한다.

각 작업은 요청ID/code/분기/근거hash/입력계약/자료파일/원고/검수/게시상태를 체크포인트로 저장한다. 중단 전 성공분은 재실행하지 않는다. Pro 한도에 닿으면 대기·reset 이후 같은 항목/단계에서 재개한다. 빈 큐·reset전 대기는 Python만 검사한다. 동시실행/중복claim/살아있는worker 재시작 방어를 보존한다. PC꺼짐·로그인소실·불확실사용량·공급자장애는 대기/실패원인을 분리하며 한도를 우회하거나 다른계정/API로 분산하지 않는다.

추가API·유료크레딧 자동구매·자동폴백0이 목표다. Pro 구독포함량은 유한하고 다른Codex/Work 사용과 공유되므로 대량처리 시간과월처리건수를 보장하지 않는다. 대표실요청에서 입력/출력·실행시간·한도감소·완료율을 계측한 후 처리량을 정한다. 실제사용량 계측 전 토큰을현금단가로 환산하거나 무제한무료라고 표시하지 않는다.

## 비용·시간 판단

이미 Pro를 유지하고 급하지 않은 과거분기를 천천히 보충한다면 API를 추가하지 않는 설계가 사용자 요구에 적합하다. 과거분기가 현재수동분석 사용량을 소진하지 않도록 낮은우선순위·중단재개가 중요하다. 과거 전체 분석에는 여러 사용량 갱신주기가 걸릴 수 있다.

이전 계산가정(기본Supabase25달러/월,환율1400원/달러,100W PC 하루4시간×30일,전력300원/kWh)을 그대로 쓰면 기존Pro 제외 월운영비38600원,Pro200달러 전액배분시318600원이다. API비용/Batch비용0을 목표로 하며 크레딧추가구매0이다. 실제인프라추가프로젝트·compute·초과·부가서비스·세금·환율은미확인이다. Pro 실제구독료를 반영해야 한다.

과거보충 때문에 PC가동이 늘면 이전전기료3600원도 증가한다. 같은100W·전력단가 가정에서24시간가동시21600원/월,기존Pro 제외56600원이다. 클라우드에서16시지표를처리하므로PC를그시간에켤필요는없지만구독Codex처리와현Telegram수신은PC/로그인/인터넷이필요하다.

## 검증·적용상태

구현 시 private 분석 큐·고정 스냅샷과 16시 지표 저장소를 분리했다. Pro 작성/검수·사용량 대기·동일 근거 재사용과 Python 유휴 실행을 검증했다. 전체 1,465 passed/3 skipped, 첫 빌드12/12, 실제 큐0/model_calls0. 초기 고정 스냅샷1,446기업/11,101분기, SK하이닉스 거래일729개 표본 저장을 확인했다. 배포·예약 적용 결과와 추가 실측은 `docs/sessions/2026-11-01-pro-only-implementation.md`에 기록한다. 검증 경계: 토/일·평일공휴일·대체/임시공휴일·정상평일의16시판정과중복실행방지,지표갱신모델0·새공시만모델0·분석버튼전고정본문불변·과거성공분재호출0·사용량대기중모델0을재생검증한다.
