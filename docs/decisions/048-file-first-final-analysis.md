# ADR48 — 파일 전달·자동 Claude·최종 Notion 단일 게시

2026-10-11 사용자 결정: 2번 방식의 장점을 살리고 단점을 보완하며 PPT 제작 직전에만 버튼을 묻는다.

## 결정

새 기업/산업 요청은 Codex가 전체 양식의 분석을 파일로 완성하고 실제 템플릿 snapshot·원문·표·차트·facts/gaps/thesis를 인계한다. 중간 Codex Notion 저장을 생략하고 기존 Claude 구독 실행기에서 자동 심층 분석을 수행한다. 최종 Notion 작성·전체 재조회 이후에만 PPT 버튼을 표시한다.

로컬 claude/원격 working-stage=claude 상태를 사용한다. 부모 sent는 Claude의 검증된 최종 Notion을 뜻한다. 기존 DB의 후속 모드·유일 인덱스를 재사용하고 부모 sent 트리거는 이미 존재하는 analysis를 재접수하지 않는다. 기존 완료 작업은 새로운 흐름으로 전환하지 않는다.

## 단점 보완

- 중간 결과 열람/복구: Codex 전체 원고·원문·템플릿과 해시 보존, Claude 원본 덮어쓰기 금지.
- 검증 독립성: 핵심 주장 독립 확인·반대 논거와 모든 gap 검색/분석, 판단 비교 표 및 검수 JSON.
- 완료/알림 오류: 파일·gap·비교·Notion 전체 재조회 후 검증 마커 저장; 상태 전환 실패는 마커만 재사용한다.
- 중복/조기 PPT: 인계 의도 먼저 보존, 유일 큐와 CAS, PPT 완료 메시지 소유자 인증, sent 재실행 금지.
- 사용량: 구독 한도 중단은 실패 횟수에서 제외하고 재설정 이후 같은 ID/세션을 재개한다.

## 한계

Notion 중간 게시 비용을 줄이지만 Claude 독립 조사와 최종 게시 비용은 필요하다. 토큰 절감률은 새 실제 요청의 실행별 usage로 측정해야 하며 추정치를 실측처럼 표시하지 않는다. 기존 60분 intake·1분 로컬 실행기를 유지한다. 공유 Codex app-server 이벤트 호출 검증 전에는 heartbeat를 끄지 않는다.
