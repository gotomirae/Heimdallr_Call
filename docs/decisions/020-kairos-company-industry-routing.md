# ADR 20 — Kairos 기업·산업 이중 라우팅과 대상별 Notion 계층

- 상태: 채택
- 날짜: 2026-09-25
- 관련: PRD §8.7, ADR 19, traps.md T167~T173

## 결정

인증된 Telegram 개인 채팅의 한 줄 입력은 `company` 또는 `industry`로 명시적으로 식별한다. 기업은 종목코드·정식명·정규화명의 단일 일치만 받고, 산업은 KRX 업종·투자 섹터·지정 Notion/Drive 카탈로그의 완전 또는 정규화 일치만 받는다. 산업 부분 일치나 문장형 입력은 분석을 시작하지 않는다. 정확한 기업명과 산업명이 충돌하면 기업을 우선한다.

`kairos_requests`는 `request_kind`와 `target_name`을 공통 앵커로 사용한다. 기업 요청만 `code`와 `company_name`을 요구하고 산업 요청은 `code=NULL`, `industry=target_name`으로 저장한다. 기존 기업 행은 `request_kind=company`, `target_name=company_name`으로 백필한다.

기업 결과는 `1. 기업 투자 분석 → 기업명 (코드·시장) → 날짜별 분석`, 산업 결과는 `2. 산업 투자 분석 → 산업명 → 날짜별 분석`에 저장한다. 같은 대상의 직전 완성본을 먼저 읽고 변경사항과 원본 링크를 새 분석에 남긴다.

진행 상태는 최근 자료 선별·산업 조사·기업 검증·웹 보완·직전 분석 비교·Notion 작성·저장 검증으로 나눈다. 완료 불가 시 `failed`와 제한된 실패 코드로 원인을 기록하고 접수 메시지를 갱신한다. Telegram 편집 실패가 로컬 단계 장부까지 잃게 해서는 안 된다.

## 이유

산업명을 종목명 해석기의 부분 일치로 처리하면 `반도체` 같은 입력이 여러 기업 후보로 바뀌거나 임의 기업으로 확정된다. 반대로 산업 요청을 가짜 종목코드에 저장하면 모든 테이블의 종목 앵커 `code` 계약을 오염시킨다. 대상 유형을 저장 시점부터 분리해야 재개·중복 방지·Notion 부모 검증·완료 메시지가 같은 의미를 유지한다.
