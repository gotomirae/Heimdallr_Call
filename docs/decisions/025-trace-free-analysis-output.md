# ADR 25 — 분석 본문에 검증 흔적을 남기지 않는다 (ADR 12 개정)

- 상태: 채택 (ADR 12의 "치환 문구" 부분만 대체)
- 날짜: 2026-10-01
- 관련: ADR 12, JARVIS INTEGRATION_TASKS B-14, traps.md T221

## 결정

1. 입력으로 검증할 수 없는 사실 숫자는 계속 **토큰 단위로 제거**한다(ADR 12 유지). 다만 본문에
   `[검증 불가 수치 삭제]` 문구를 남기지 않는다. 다른 문장이 남는 필드면 그 숫자가 든 **문장째**
   빼고, 문장이 하나뿐이면 토큰만 지운 뒤 공백·빈 괄호를 정리한다. 삭제 사실은 지금처럼
   `_heimdallr.removed_factual_numbers`에 남고 대시보드가 건수를 알린다.
2. 정상 참조(`[[F001]]`·`[[F001:원문]]`)를 복원한 뒤에도 남은 `[[…]]` 표식은 단위가 붙은 숫자면
   그 값으로 풀어 **동일 단위 근거 검사를 다시** 받게 하고, 단위 없는 원시값
   (`[[F announcement_return_pct -11.375]]`)은 지운다.
3. 배열 안에서 문자열 값이 자리표시(`...`·`…`·`placeholder`·`TBD`·`N/A`)인 객체 항목은 저장 전에
   뺀다. 배열이 비면 기존 스키마 검증이 `empty`로 잡아 저장하지 않는다.
4. 기존 저장분은 `python -m src.analysis.clean_stored_run --save`로 LLM 호출 없이 같은 규칙을 적용한다.
   단일 문자열 자리표시(`earnings_change.cause = "placeholder"` 등)는 빈 값으로 바꾸고, 정리로 **새로**
   비워진 칸을 `_heimdallr.b14_emptied`에 남긴다. 분석 전체를 숨기지는 않는다 — '몇 칸 이상이면
   숨김' 기준은 자의적이고, 한 칸 때문에 유효한 해석까지 잃는다(T223).
   2026-10-02 실행: 399건 중 34건 정리 · 숨긴 분석 0 · anon 재조회 `[[` 0 · 흔적 0 · 자리표시 0.
   토큰 제거 시 바로 붙은 조사('라는'·'대를')도 함께 빼 고아 조사를 남기지 않는다.

## 이유

JARVIS가 이 payload를 사용자 화면·브리핑에 그대로 싣는다. 흔적 문구와 사실 표식은 읽는 사람에게
"분석이 깨졌다"로 보이고, JARVIS가 표시 단계에서 매번 따로 지워야 했다. 근거 없는 숫자를 막는
목적은 토큰 제거와 메타 기록으로 이미 달성된다.

## 되돌리면 무엇이 무너지는가

- 치환 문구를 되살리면 연계 소비자가 다시 문자열 후처리를 떠안는다.
- 깨진 표식을 그대로 두면 `[[F 218.8억]]`처럼 근거 검사를 **우회한 숫자**가 저장된다 —
  복원 정규식에 안 걸린 표식은 숫자 검사 대상 텍스트로도 읽히지 않았다.
- 자리표시 항목을 남기면 `"..."`가 None도 빈 문자열도 아니라서 검증을 통과해 화면에 뜬다.
